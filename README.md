# OP_USZ-msp

This repository contains the code to detect the midsagittal plane on planning CT scans from the University Hospital Zurich (USZ) using our [mspdetect] package. Unfortunately the planning CT scans are not publicly available, however the patients used here are a subset of the [2021-USZ-oropharynx] dataset whose nodal involvement patterns are publicly available and can also be queried on [LyProX].

[mspdetect]: https://github.com/lycosystem/mspdetect
[2021-USZ-oropharynx]: https://github.com/lycosystem/lydata/tree/main/2021-usz-oropharynx
[LyProX]: https://lyprox.org/

The detected MSPs together with the nodal involvement patterns are the basis of [our publication], which investigates modelling of contralateral nodal involvement taking into account how far the primary is from the midline or extends across the midline.

## Pipeline
While our planning CT scans are not publicly available, you can use this pipeline to run the MSP detection on your own CT scans. For this follow the guide below.

### Prerequisites
To follow this guide you need the following tool installed on your system:

- [uv] for creating isolated virtual environments

Please refer to the respective link for installation instructions.

> [!NOTE]
> [uv] is not strictly necessary. But due to its cross-platform lockfile, its integrated Python version management and its insane speed compared to stuff like `venv` or `pip`, we highly recommend it.

[uv]: https://docs.astral.sh/uv/

### Setup Instructions
1. **Clone the Repository**
    Clone this repository to your local machine: 

    ```bash
    git clone https://github.com/noemibuehrer/OP_USZ-msp.git
    cd OP_USZ-msp
    ```

2. **Set up and sync the Virtual Environment**
    Use `uv` to create, sync and activate a virtual environment:

    ```bash
    uv sync
    source .venv/bin/activate
    ```

3. **Put correct input path**
    Change the path in the config file `config.yaml` in the directory `msp_pipeline/configs/` such that it fits your data. You also need to change it in the `dvc.yaml` in the stages `run-mspdetect` and `calculate-metrics`. The package expects a directory containing CT scans with binary structure masks in NIfTI. More details can be found in the [documentation] of the mspdetect package.

[documentation]: https://mspdetect.readthedocs.io/

4. **Run Computations**  
    To run the pipeline: 

    ```bash
    dvc repro
    ```

    For further information, consult the [dvc documentation].

    [dvc documentation]: https://dvc.org/doc


### Outputs
The pipeline will generate a `metrics.csv` file in the `msp_pipeline/metrics` directory containing the metrics related to the detected MSP. The stage `export-first-start` in `dvc.yaml` reformats this metrics file to `metrics_first_start.csv` which only contains the first starts of the optimisation, in case of multiple starts. In `msp_pipeline/results` one directory per patient is generated, storing the MSP parameters among other information.

### Analysis notebooks
The notebooks in `multistart/`, `midext_discrepancy/` and `view_patient.ipynb` document the analyses for our publication. They require the non-public planning CT scans and structure masks of our cohort, or results derived from them (the pipeline outputs in `msp_pipeline/results` and `msp_pipeline/metrics`, and for `midext_discrepancy/` the 2021-USZ-oropharynx table with the algorithmically assessed midline extension added). They therefore cannot be re-run without access to this data and are included for transparency.
